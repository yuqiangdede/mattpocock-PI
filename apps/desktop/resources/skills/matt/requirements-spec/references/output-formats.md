# 交付格式制作与检查

中间与最终文档的位置及命名按 [document-flow.md](document-flow.md) 执行。中间文档默认 Markdown，用户另有指定时执行对应格式分支；最终仅执行已选择格式。用户指定多种最终格式时共享同一融合内容基准，内部草稿不自动作为额外交付件。

缺少工具时遵循 SKILL.md 的工具安装授权规则：使用者明确允许后可自动安装，检查工具可用性后继续相应格式的制作与验证。

## 共用规则

核对转换前后各类型需求/规则数量、唯一编号及引用、业务分类、步骤、公式和图片，差异分析保留现状与目标两侧及其缺口。正文中的 HTML/Markdown 控制文本应转成目标格式，不残留在可见内容中。功能用例保留用户要求的字段—描述结构，其他类型保留其专用字段；L1 保持功能清单结构。

参考图片从临时目录复制至交付目录 assets；DOCX 嵌入图片。Markdown 与 HTML 优先采用同目录相对路径以便携带，聊天中的文件或图片链接使用绝对路径。不得只引用剪贴板临时文件或某台机器的绝对路径作为便携文档依赖。

既有图片不擅自重绘或修改；架构图清晰按比例展示并有图题。中间文档可保留可信度、源码追踪及分析记录；最终文件不包含需求可信度、源码依据、文档依据、来源索引或编制痕迹。默认假设及 QA 图片不进入最终文件，已选保留的真实业务缺口按规则处理。

### Mermaid 图形

业务流程图与状态图以 Mermaid 源码为可维护基准。Markdown 保留 mermaid 代码块；检查语法及实际可用预览，未渲染时只报告源码检查。

HTML/Word 使用现有可用渲染工具生成实际图形：HTML 优先本地 SVG 或 PNG，Word 使用受生成工具支持的嵌入图形（通常 PNG）。HTML 不依赖联网 CDN 才能显示图形。图题、图号及正文引用一致；检查中文、连线、条件分支、状态含义、缩放和打印分页，嵌入后再做格式的视觉检查。Mermaid 源码和图形保持同步，不把代码块当成已交付的图形。

缺少渲染器先检查已有工具，安装遵循主技能授权规则。暂时不能渲染时保留源码与已有成果，明确图形交付限制；若图形是所选交付件的必要内容，不宣称完整交付或视觉检查通过。

## Markdown

生成 UTF-8 Markdown，标题层级、表格和空行符合规范。多步骤用 <br>。核对图片路径、编号、内部引用和语法；如果没有可用预览，只报告实际文本和结构检查。

## HTML

生成本地静态可携带 .html 及必要 assets，正文为真实文本和表格；不发布网站，不因文档采用 HTML 自动引入 Sites 流程。

使用中文字体、清晰标题、页内目录、合理的标签/描述列宽和打印样式。表格内容自动换行；屏幕窄宽时保持可读。打印时隐藏交互导航、重复表头并避免切断标题和短行。图片按比例缩放；内置 CSS，无业务执行脚本或追踪器。

使用可用浏览器查看长流程、图片、多页表格和打印预览，检查溢出、乱码及分页；修改后复核。浏览工具不可用时说明验证限度。

## Word

读取当前可用 documents 技能的 SKILL.md，遵循其运行时加载、操作标记和 render-and-verify 规范。通过依赖加载工具定位 bundled runtime，不使用硬编码插件版本。doc-coauthoring 不替代 DOCX 生成器。

### 生成方式与安装授权

优先用 python-docx 直接构建 .docx，所需目录域、页码域和高级表格属性通过 OOXML 补充。先将内容基准解析为统一内容模型，HTML 与 DOCX 分别从该模型生成，避免依赖 HTML 导入 Word 的转换链路；字体、段落和表格规则集中定义为样式。

检查所选 Python 运行时能否导入 docx。缺少 python-docx 时，向用户说明它用于直接生成 Word、所用 Python 环境及安装位置，取得明确允许后执行该解释器的 `-m pip install python-docx`，再验证导入并继续生成。已有会话中的明确安装授权直接沿用；要求生成 Word 本身不等于允许安装依赖。未获允许或安装失败时，使用可用的兼容方案或保留已有成果并说明限制。

直接构建不可用时才考虑现有 HTML–Word COM 方案；验证当前 Word 对列宽及页面 CSS 的实际导入效果。不得为提速自动引入 pandoc、LibreOffice 等额外工具；确需安装时仍遵循安装授权规则。

### 分阶段执行与失败恢复

生成脚本新增或修改后，先用约两页的探针文档验证受影响逻辑，覆盖目录、中文、长表格与跨页表头、图片及页码，再生成全量文档。探针用于提前发现错误，不替代最终全量检查。

将内容解析、DOCX 构建、结构校验、域更新与分页、渲染检查分成可单独执行的阶段，保留已成功的产物。失败后定位原因，只重试受影响阶段；避免脚本调试、域更新或导出失败反复触发全量构建。记录各阶段实际耗时，用于识别瓶颈，不承诺固定秒数或三分钟内完成。

需要 Word 更新目录页码时，尽量使用一次独立会话完成打开、更新域与目录、重分页、分页检查和保存，避免重新打开文档逐段遍历。按分页是否稳定判断是否需要再次更新；`w:updateFields` 仅是客户端更新请求，不能作为目录页码已更新并保存的证据。

为打开、保存和导出设置合理超时；发生挂起时停止该路径，保留直接生成的 DOCX，排查写盘路径和 Office 环境后再重试失败阶段。只清理本次创建且能够确认归属的 Word 进程，保留用户已有会话。PDF 导出不是唯一渲染途径，失败时可使用可用的其他实际渲染方式。

### 样式与版式

以内容基准制作 .docx；用户有模板时模板优先。无模板按 documents 当前模板选择规则决定正式规格书样式：
- A4、适当页边距、可读中文字体和一致标题层级。
- 封面填写已知项目、名称、版本及日期，不编造作者或审批。
- 真正 Heading 样式、TOC 目录和页码字段；更新目录后核对页码。
- 每项用例采用真实可编辑两列表格；标签列约 20%～25%，过程步骤逐段展示。
- <br> 转换为换行/段落，不能在 Word 显示原控制字符串。
- 表格重复表头、允许文字扩展；短行避免跨页，长流程合理分页，避免整表锁定导致大片空白或截断。
- 图片嵌入并加图题，字段、枚举和公式完整可读。
- 字体、边框、颜色和页眉页脚按用户模板或 documents 现行规范统一。

### 三级校验

1. **内容检查**：核对需求数量、唯一编号、字段、步骤、公式、图片引用及残留占位标记，与内容基准逐项对应。
2. **OOXML 结构检查**：直接读取 DOCX ZIP 内的 document.xml、styles.xml、settings.xml、页脚及关系文件等，检查标题样式与大纲级别、TOC 和 PAGE/NUMPAGES 域、表格重复表头与列宽、图片嵌入和残留标记。避免为这些检查再次启动 Word；结构检查不能证明实际目录页码或显示布局正确。
3. **实际排版检查**：需要确定页码时通过 Word 或可用排版引擎更新目录并核对实际分页。渲染为每页 PNG，打开所有页面核对表格、图片、目录、页码、文字截断与中文字符。修复后重新渲染受影响内容并检查最终全量页面。文本或 OOXML 检查不能替代视觉检查。

区分“已生成且结构检查通过”“目录页码已更新并保存”“全页视觉检查通过”，只报告实际完成的状态。

明确要求 .doc 时通过真实兼容工具转换并检查，不能改后缀。缺少转换或渲染器时保留现有输出并报告具体限制；不能声称视觉验证通过。

## 交付门槛

选定格式全部生成且可打开，内容与基准一致，编号唯一，图像可携带。Word 全页视觉验证，HTML 实际浏览与打印检查。无法完成的验证如实说明。

分别链接实际生成的中间文档与选定格式的最终文档，用户限定交付阶段时沿用限定；QA PNG、PDF 和其他辅助笔记默认内部保留。格式转换不得修改已选择的待确认保留策略。最终全部格式均检查来源字段和编制痕迹已清除，正文无需依赖中间文档即可阅读。
