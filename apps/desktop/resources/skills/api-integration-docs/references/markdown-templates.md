# Markdown 交付结构与模板

## 默认文件

```text
docs/integration/
├── README.md
├── api-index.md
├── connection-guide.md
├── http/<接口编号>-<简名>.md
├── messaging/<接口编号>-<简名>.md
├── protocols/<接口编号>-<简名>.md
├── schemas/shared-models.md
├── integration-guide.md
├── source-traceability.md
├── verification-report.md
└── open-questions.md
```

按实际协议建目录，不生成无内容的协议章节。示例默认嵌入对应接口 Markdown，较长示例可另存 examples/*.md 并链接。小项目可合并，但合并前后的内容覆盖要求相同。

| 文件 | 内容 |
| --- | --- |
| README | 项目用途、版本/源码基准、材料范围、接口总数与协议分类、服务归属、业务关系、阅读顺序 |
| api-index | 接口编号、名称、协议、方向、入口、状态、启用条件、正文链接、分析及验证进度 |
| connection-guide | 拓扑与网络前提；环境地址配置、Base URL/前缀/版本、Broker/端口/协议版本；TLS/双向证书、账号获取、令牌有效期、签名算法/排序/时间戳/验签；租户与权限/白名单；编码/日期/时区、大小/超时/频率/并发限制。未知项标注待环境确认 |
| shared-models | 公共头、认证结构、响应包装、分页/排序、日期/坐标、字典枚举及错误码；提供完整字段和各接口引用 |
| integration-guide | 获取环境凭据→网络连通→认证/建连→最小有效请求→确认结果→典型错误→必要重试/幂等→上线配置；有真实业务链时提供端到端场景 |
| source-traceability | 来源清单、接口与关键结论的证据定位、确认标签、实现/约定差异与排除记录 |
| verification-report | 覆盖范围与计数、静态检查、实际运行命令及结果摘要、未验证项与原因，不保存秘密 |
| open-questions | 缺失信息、影响接口、接入阻碍、需要谁确认什么及建议验证方式；无缺口时明确无 |

## HTTP 接口模板

以下占位表示需要填入实际证据；缺失内容写“待确认”和影响，不能为完成模板而猜测。

```markdown
## HTTP-001 <业务接口名称>

<业务用途、所属模块、调用前提和相关接口>

| 属性 | 说明 |
| --- | --- |
| 接口地址 | `<实际完整路径；Base URL 见对接准备>` |
| 请求方式 | `<HTTP 方法>` |
| Content-Type / Accept | `<实际媒体类型>` |
| 认证、授权与签名 | <规则或公共规则链接> |
| 调用方向 | 第三方系统 → 本系统 |
| 版本、状态与启用条件 | <适用范围> |
| 契约与实现状态 | <确认类型及证据编号> |

### 请求字段说明

| 位置 | 字段路径 | 类型 | 必填性 | 可空性/空值处理 | 默认值 | 含义与约束 | 示例 | 依据 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Body | `location.longitude` | number | 条件必填：提供 location 时 | 不可 null | 无 | 经度，范围及坐标系以实际约定为准 | <有效数值> | SRC-xxx |

<分别覆盖 Path、Query、Header、Cookie、Body、Form、Multipart；无参数的位置可注明不适用。说明缺失、null、空字符串、空数组的区别及字段依赖、互斥。文件说明字段名、类型、大小和编码。>

### 完整请求与 curl

<完整 HTTP 请求，包括必要请求头和正文；独立的 bash 代码块给出 curl。注明地址/凭据占位符获取方式、示例验证状态。>

### 响应字段说明

| 响应分支/HTTP 状态 | 字段路径 | 类型 | 出现条件/可空性 | 含义与约束 | 示例 | 依据 |
| --- | --- | --- | --- | --- | --- | --- |
| <实际分支> | <真实传输字段> | <类型> | <条件> | <说明> | <值> | SRC-xxx |

<逐层展开顶层包装、数据和分页；分别给出完整成功响应及有证据的参数错误、认证/业务失败响应。区分 HTTP 状态与业务码；说明空结果、部分成功和异步受理。流和二进制响应按实际格式描述。没有依据的失败报文保留缺口。>

### 业务规则与错误处理

<生效条件、前置状态/状态流转、同步或异步、重复创建、幂等键及作用范围、超时、重试和边界条件；写明每条规则的依据。>

### 证据与待确认事项

<注册、模型、校验/安全、处理、响应/异常、测试/配置的相对路径及行号；关键结论标签和缺口链接。>
```

实际项目无 location 字段时替换整行；该行只演示嵌套字段写法。字段可通过公共模型链接复用，但链接目标必须完整，调用者不需要查看源码。

## 其他协议

沿用基本信息、字段表、完整交互、成功/失败、业务规则、证据的共同结构，再补协议专属内容：

- WebSocket：URL、握手/认证、子协议、消息类型与方向、心跳、关闭与重连。
- gRPC：服务方法、请求/响应消息、单次或流式、Metadata、状态码。
- TCP/UDP：监听配置、帧布局、分包粘包、字节序、长度/校验、应答与超时。
- 文件：投递位置、命名、格式/字段、触发、成功标识、失败及重复处理。
- SOAP/GraphQL：分别补充命名空间/Action/Fault，或操作、变量、Schema、data/errors 及传输约定。

## 示例规则

完整报文必须可解析并匹配字段表；枚举、日期、精度、单位和时区一致。未知结构不编造“完整成功响应”，明确缺口。非运行采集的示例注明“依据源码构造，未经运行验证”或“依据文档构造，未经实现核验”。使用虚构值和 example.com 等示例地址；凭据采用清晰占位符，避免真实账号、令牌与个人信息。命令可复制，但占位符替换前提必须写清楚。
