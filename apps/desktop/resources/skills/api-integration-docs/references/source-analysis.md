# 源码反推指南

## 边界与入口

从构建文件、依赖、启动入口、模块、部署配置识别系统边界，检查实际注册和条件启用：

| 类别 | 搜索入口及需核实的行为 |
| --- | --- |
| HTTP | 路由、注解、Servlet、动态注册、REST、Webhook、SOAP、GraphQL、表单、上传及二进制接收；组合网关、context path、版本及路由前缀 |
| 消息 | Kafka、RabbitMQ、RocketMQ、MQTT、Redis Stream/PubSub、JMS、Pulsar、自定义消息总线的消费者、订阅及分发注册 |
| 连接协议 | WebSocket 握手与消息处理、gRPC 服务注册、TCP/UDP 监听、自定义长连接和二进制解码器 |
| 文件与回调 | FTP/SFTP、目录监听、文件投递、第三方 SDK 注册回调及其他外部数据接收边界 |

技术清单用于发现入口，最终以实际代码为准。排除内部普通函数、未暴露服务方法、主动发起的 HTTP 请求、生产者发送、测试 Mock、未注册/被禁用/已删除入口；保留排除理由。条件入口注明 profile、feature flag、部署及配置条件。只有内网可用、仅供第一方页面或管理端使用的入口需标明访问对象与限制，不能自动视为第三方公开 API。

系统主动调用/发送可列外部依赖附录。Webhook 的接收入口属于输入，回调返回或同一长连接的服务端输出属于该交互响应，不能因排除主动发送而省略完整协议。用户指定双向对接时扩展方向并分别标识。

## 每接口追踪闭环

1. 注册/订阅/监听 → 配置、前缀、环境和可达性。
2. 中间件/过滤器/拦截器 → 认证、权限、租户、签名、白名单。
3. 解析器/DTO/Schema/序列化器 → 别名、忽略字段、命名策略、日期、数值精度、null、继承、泛型、多态及实际外部格式。
4. 校验注解、手动校验及业务分支 → 条件必填、默认值、互斥、范围、单位、枚举、文件及大小限制。
5. 核心处理 → 同步/异步、状态变化、事务、去重、幂等及可观察结果。
6. 返回值 → 全局包装、异常处理、真实 HTTP 状态、业务错误码、多响应分支、流/文件响应。
7. 测试、配置、协议声明、已有文档交叉核对；记录定位和仍缺失的证据。

不要只根据 Controller、DTO 或声明生成最终行为。验证路径与 Topic 使用实际注册配置，不把注解中的相对值当最终地址。Broker 和服务器真实地址无法确定时写配置键及“待环境确认”，不泄露凭据或内网敏感数据。

## 消息与其他协议专项

消息：查 Broker/协议版本、Topic、Queue、Exchange、Routing Key、Consumer Group、通配订阅、QoS、Key/Header/ID、编码；追踪 ACK/NACK/Offset 的提交时点、异常捕获、重试次数和间隔、死信、过期、过滤、顺序、批量、并发和事务。区分中间件投递保障、客户端库默认值与应用业务成功；默认值须有依赖版本/有效配置依据。未发现去重或死信实现时如实说明，不以中间件通常具备的能力代替项目事实。

WebSocket：握手认证、URL、子协议、帧/消息类型、双向字段、心跳、关闭码与重连。

gRPC：proto 与实际注册服务、方法、消息、流式模式、Metadata、状态码及截止时间。

TCP/UDP：监听配置、帧边界、分包粘包、偏移、长度、字节序、编码、校验、应答及超时。

文件：路径配置、命名与格式、字段、触发、原子写入/完成标识、成功确认、失败归档与重复文件处理。

每项已识别入口都建立源码映射：注册、参数模型、校验与安全、核心业务、响应或消息处理、测试及配置。无对应实现的位置明确标为未发现，不强行补齐。
