# 多来源融合

## 提取与定位

为每份来源分配 SRC 编号，记录标题、类型、路径/链接、版本/日期、适用服务和证据定位。源码定位使用仓库相对路径和行号；文档使用章节、页码、表号、工作表/单元格或 Markdown 标题。记录 Git Commit（可获得时）、工作区未提交状态；非 Git 项目使用实际版本或目录快照说明，不能虚构 Commit。

| 来源 | 提取内容 | 不能单独证明的内容 |
| --- | --- | --- |
| 源码 | 实际入口、处理链、传输结构、校验、异常与配置条件 | 生产环境已部署、业务原始意图、未实现目标 |
| 需求与设计 | 场景、调用顺序、目标契约、状态流转、非功能约束、ADR 决定 | 当前实现与部署已经符合约定 |
| 参考文档 | 第三方协议、既有接口、字段字典、兼容要求、格式 | 本项目支持参考材料的全部能力 |

格式参考只约束写法，不将示例地址、字段、错误码移植为真实接口。第三方协议须核对协议版本、角色及本项目实现子集。

## 同一接口的合并

先确定系统边界和调用方向，再以服务、协议、HTTP 方法+规范路径、Topic/Queue+事件类型、gRPC 服务方法等建立身份。相似名称不能直接视为同一接口；不同协议可描述同一业务事件，但保持独立契约并说明关联。参数顺序、别名、大小写、单位、时区和版本差异逐字段核对。

当前实现文档中，已要求但未注册/未实现的入口列入“目标接口与差距”，不计入已可调用接口数。目标契约文档中保留有效目标要求，同时显式标记实现状态。差异模式并列展示约定、实现和接入影响。

冲突表至少包含：问题编号、接口/字段、来源及各自结论、适用版本、已查证结果、接入影响、采用口径、待确认责任项。优先核实不同版本、配置、网关、序列化及全局包装造成的表面矛盾；只有明确的修订/废止关系才能据此替代旧约定，不能仅凭文件日期或来源类别静默覆盖。

## 结论标签

- **已确认（源码/文档/运行）**：给出能够支撑该结论的具体位置和适用条件；文档依据只确认约定。
- **推断待验证**：注明推断依据、缺少的证明及验证方式，不能用于断言成功响应或安全机制。
- **待确认**：材料无法给出结论，记录需获取的环境信息或业务决定；部署地址标为“待环境确认”。

材料空缺与能力缺失分开表述：“未发现实现”包含已搜索范围，不等于证明系统绝对不支持。无法读取的来源保留在来源清单，状态为未纳入。
