# 质量检查与验收

## 覆盖与准确性

- 将发现清单逐项对照正文：纳入接口均有唯一编号和可达链接，排除/条件可用/目标未实现均有记录；协议分类计数与总数一致。
- 对照实际注册与配置检查路径、方法、Topic、前缀及版本；核对序列化别名、嵌套、数组、枚举、公共包装、响应分支和异常处理。
- 必填、可空、缺失、默认值、约束、认证、安全、幂等及重试结论都有依据；文档要求、实现事实和运行结果明确区分。
- 每个关键结论能回溯源码路径/行号或文档章节/页码；未实现能力与未知信息保持显式，不复制参考示例为项目事实。

## 示例与 Markdown

- 使用实际可用解析器检查 JSON、XML 等结构；含占位值仍应保持语法合法。未能运行解析器时说明未检查，不能仅凭目视宣称解析通过。
- 将报文字段、必填、枚举、约束和响应分支与表格双向核对；区分完整示例与仅供说明的片段。时间戳与显示时间并用时校验换算。
- 检查 curl/发布命令的引号、转义、Content-Type、认证头、目标路径及实际协议工具参数；命令语法有效不等于已真实调用。
- 检查表格列数、管道符转义、代码围栏、相对链接与锚点；UTF-8、无替换字符 U+FFFD。删除未填模板占位；有意保留的环境/凭据占位说明获取与替换方法。
- 示例中不泄露秘密或真实个人信息。执行前确认环境和副作用授权；无法运行时交付准确的未验证状态及验证步骤。

## 从第三方视角审阅

逐接口检查能否回答：连接哪里、怎样认证、发送什么、每个字段什么意思、什么结果算成功、出错如何处理、如何确认消息已被业务接收、如何完成独立联调。每个无法回答的问题都进入缺陷或待确认清单，标记是否阻断接入。
