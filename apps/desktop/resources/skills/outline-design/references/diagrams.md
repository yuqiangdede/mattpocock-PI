# 设计图形与 diagram-design

## 使用方式

用户已选用 GitHub 项目 [cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design) 作为强制制图能力。所有模块关系、关键流程、时序、状态、ER 与数据流图均必须通过 diagram-design 规范制作，不得随意使用其他格式替代。实际制图时检查可用技能/插件；可用时读取当前安装的 SKILL.md，再读取所选图形类型与导出参考。不要硬编码某个发布版本、插件路径或命令形式。

其主要成果是内嵌 SVG 的独立 HTML，可按当前工具能力导出 SVG/PNG。它负责布局与视觉表达，架构、接口、状态和关联关系由本设计的分析与决定提供。仓库在线说明不等于本机已安装或导出成功。

未安装时明确说明缺少强制制图能力 diagram-design；若确需安装，按本会话的有效授权执行，无安装授权则提出所需工具、位置和用途并等待决定。未安装完成前仅可继续文字设计与图形语义稿编制，不得使用其他工具替代正式图形或交付不合规图形，绝不冒称通过 diagram-design 制作。

## 图形语义稿

优先依据 source-and-merge.md 的流程清单和组件协作分析选择图形。需求推导的图明确目标方案，源码反推的图仅画已证实关系；跨组件图核对接口两侧与数据归属，不能仅按参考图的形状替换名称。

每张图先记录图号、标题、所回答的问题、适用现状/目标、节点及职责、关系及方向/标签、关键条件、图例和正文位置。语义稿保存在本阶段图形目录，必要时用 Mermaid 或结构化文本描述，更新图形时同步。

逻辑架构、运行构件和部署节点采用独立视图并可对照。时序图说明调用方/提供方和正常/异常分支；状态图说明状态、触发和守卫；ER 图说明实体和真实基数，不因字段同名就补造关系。设计建议的实体、接口和拓扑明确目标口径，不画成当前已部署事实。

图形表达复杂时拆主图与局部图，保留稳定标识和必要关系；不能为美观删去关键模块、约束、箭头、失败分支或多重性。不同类型图的节点不强制统一成一种形状。

## 专业视觉规范

用户模板及企业规范优先；无指定品牌时使用正式文档风格：白底、深灰正文、深蓝强调、灰色辅助线，平面清晰、静态、适合打印，不使用装饰动画、拟物图标或大面积深色背景。强调色用于层次与关键关系，颜色含义有图例；不能仅靠颜色区分重要状态。

建议项目样式语义：paper #FFFFFF、ink #1F2937、accent #244A73、muted #64748B、hairline #CBD5E1，字体采用实际可用且支持中文的字体。图形与文档字号/命名协调；打印后标签仍清晰，长中文不被裁切。

使用 diagram-design 时先检查现有项目 profile。已有规范沿用；没有规范时把上述文档样式作为项目级方案，按当前技能的 profile/onboarding 机制应用。上游明确要求用户选择时结合既有选择判断，仍需确认则引用实际读到的 SKILL.md 及规则说明原因，继续其他工作；不擅改全局样式或其他项目的 profile。

## 输出与检查

图形默认放在目标项目 docs/Design/assets/diagrams/ 下的总体设计或概要设计阶段子目录；用户指定目录优先。使用阶段与图号区分文件，避免两技能互相覆盖。每图保留语义稿及可维护 SVG 等源资产；正式 Markdown 通过相对路径引用 SVG/PNG，图形语义稿中可保留 Mermaid 代码块。HTML 仅可作为制图工具的内部源稿，不作为文档交付格式。

图形格式转换必须真实执行并检查，不能只改扩展名。必要时保留矢量稿和 PNG，不能仅提供屏幕截图或远程临时链接作为唯一资产。图形布局不依赖联网字体/CDN才能阅读；使用现有工具导出，不自动安装工具。

逐图核对节点、方向、标签、数量关系、条件与正文；实际查看渲染结果，检查中文、连线交叉、文本遮挡、边距、图题和比例。在 Markdown 可用预览中检查可读性，大图适当拆分。语义稿、原始 HTML/SVG与嵌入图片必须表达同一设计。

只报告实际完成的语义、渲染、导出及嵌入检查。缺少渲染/导出能力时保留已有成果并列出限制；必要图形未制作或未校验时，不声明图形全部交付通过。

完成条件：每张必要图有明确问题、正确语义、统一风格、可携带资产及对应正文引用，图文一致且实际可读；多画装饰图不算完成设计。
