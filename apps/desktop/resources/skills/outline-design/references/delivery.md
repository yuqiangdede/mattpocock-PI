# Markdown 制作与交付

## 输出与内容基准

中间与最终文档均仅生成 UTF-8 Markdown（.md），无需询问格式。逐文件路径优先于阶段目录，阶段目录优先于共同目录，否则使用技能入口默认值；相对路径以目标项目根目录解析。不能覆盖原输入、其他阶段或无关文件。

多个组件材料融合为一份概要设计，执行 [source-and-merge.md](source-and-merge.md)。统一目录、概述、术语和编号，重建跨组件流程；保留组件职责与契约差异，不能顺次拼接后称为融合。用户仅要求某一阶段时按其范围执行。

## 正式 Markdown

用户模板的内容结构优先。每章先交代目的、设计结论与边界，再说明机制与取舍；表格用于职责、接口、状态、数据约束及异常，长解释使用段落。编号、图题、表题及交叉引用稳定一致，不编造审批、指标或标准符合性。

清理可信度、源码位置、来源索引及编制叙述，保留工程标识、设计理由、真实限制和选定待确认项。概要设计覆盖模块协作、接口契约、状态、数据及异常，遵守技能入口的设计深度。

使用规范标题、列表、表格和代码围栏；表格内换行可用 `<br>`，公式保留 LaTeX。图片复制至 assets 并用相对路径引用；制图规则见 [diagrams.md](diagrams.md)。Mermaid 保留代码块，已有 SVG/PNG 可作为图片资产，内部制图源稿不成为 HTML 文档交付件。

## 检查与交付

校审正文、表格、图形语义、需求覆盖与跨组件引用。检查中文、编号、路径、围栏、表格及缺口处理；有预览工具时查看长表和图形，无工具时只报告文本与结构检查。

分别链接实际生成的中间和最终 Markdown 及必要 assets。另需 Word 时，在 Markdown 定稿后使用独立的 markdown-to-docx 技能，不在本技能内实现转换。报告范围及实际内容、结构和图形检查状态；不将校审称为运行测试、客户批准或部署成功。

完成条件：约定范围的设计完整、关键缺口明确、Markdown 文件存在、图片可携带、引用有效，实际检查如实说明。
