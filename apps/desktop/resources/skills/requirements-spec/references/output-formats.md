# Markdown 制作与检查

中间与最终文档均仅生成 UTF-8 Markdown（.md），位置及命名按 [document-flow.md](document-flow.md) 执行，无需询问格式。Word 转换由独立的 markdown-to-docx 技能承担。

## 内容与结构

核对各类型需求/规则数量、唯一编号、内部引用、分类、步骤、公式和图片。差异分析保留现状与目标及其缺口。功能用例保留字段—描述结构，其他类型保留专用字段；L1 保持功能清单结构。

标题层级、列表、表格及空行符合 Markdown 规范；表格内多步骤可用 `<br>`，单元格中的竖线正确转义。公式使用行内或块级 LaTeX，代码使用带语言的围栏，避免以截图替代可编辑正文或表格。

中间文档保留可信度、依据与分析记录；最终文件移除来源索引及编制痕迹，保留有效业务约束和按人工选择处理的真实缺口，正文可独立阅读。

## 图片、图表与 Mermaid

参考图片复制到交付目录 assets，以相对于 Markdown 文件的路径引用；保留原始图表数据，不擅自重绘既有图片。图题、图号及正文引用一致，不能只引用剪贴板、临时文件或某台机器的绝对路径。

业务流程图与状态图保留 mermaid 代码块，检查节点、分支、状态与正文一致。有渲染工具时检查实际预览的中文、标签与连线，无渲染器时只报告源码检查。统计图表使用已有图片或明确数据的图表源，不能编造数据。

## 交付

检查 UTF-8、图片路径、编号、引用、表格及围栏。有可用预览时检查长表与图形，未预览时说明检查限度。

分别链接实际生成的中间与最终 Markdown，以及必要 assets，用户限定阶段时沿用。聊天文件链接使用绝对路径，文档内图片使用便携相对路径。完成条件是范围内内容完整、文件存在、资产齐全、引用有效，检查状态如实说明；不以文档校审代替代码或现场验收。
