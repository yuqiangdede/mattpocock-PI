# 转换验证与交付

## 内容与结构：所有验证级别均必做

新增或变更转换逻辑时，先用覆盖本次实际特性的最小探针（如中文、嵌套列表、表格换行、长表、图片、公式、Mermaid 和数据图表）验证所用转换工具。现成依赖或脚本 `--check` 只说明依赖情况，不能证明渲染链路兼容。

合并模式必须执行两段相互独立的核对：**全部组件输入 → 融合 MD** 的章节顺序、输入条目去向、重复/遗漏、冲突及业务差异；**融合 MD → DOCX** 的内容和结构一致性。人工指定名称需在 MD 标题、文件名、Word 封面/标题区一致，模板或 profile 的选择不能遗漏正文。

通过实际解析与对照检查标题层级及顺序、章节重复/遗漏、段落和列表顺序、唯一业务编号、表格行列及单元格文本、脚注、链接、公式、图题、图片数量与语义。检查关键流程、单位、符号及图表数据没有被改写。元素数量、关键短语存在和抽样文本均仅为辅助证据，**不能单独证明全文一致**；发现差异时定位到对应章节并处理或列明缺口。

检查 DOCX ZIP、正文、样式、图片与关系可解析，图片为嵌入资源，标题为真实 Heading 样式，表头与代码/公式实际转换。不得残留 mermaid/chart 原始代码、缺图占位符、临时路径或原始 HTML 控制文本。生成失败或内容/结构不完整时，不得借用“跳过视觉检查”宣称通过。

## 视觉验证级别

遵守[共享工具选型与验证策略](../../_shared/TOOLING_POLICY.md)。视觉检查与上述必做项分离，普通单文档转换**默认快速**；当有企业固定版式、封面、准确目录页码、复杂长表或正式外部交付要求时，推荐相应提升级别并说明开销。用户已作出的选择在本次工作流中复用，只有用途或风险变化时再次提示。

| 级别 | 必做内容 | 排版处理及结果边界 |
| --- | --- | --- |
| **快速（默认）** | 全部内容/结构必检项 | 不为排版额外导出 PDF、渲染每页或启动 Office。核对 TOC/PAGE 域的存在性，但不声称实际页码已更新或版面已核验。 |
| **标准（按需）** | 快速 + 代表性页面视觉抽查 | 按风险挑选封面、目录、长表、复杂图形/公式等少量页。优先采用已有可信预览能力；若只能经 PDF 导出进行抽查，先提示额外成本，用户可选择跳过。报告实际抽查页，不宣称全页通过。 |
| **严格（推荐给正式交付）** | 快速 + 实际排版引擎重分页、按需更新域、全页渲染与逐页检查 | 检查中文字体、换行、留白、图像清晰度、连线、表格跨页、孤行、目录和页码、公式。用户可明确选择跳过耗时的**全页视觉检查**，但相关视觉结果标记“用户选择跳过”，不能宣称符合固定版式。 |

“跳过 PDF 排版验证”只省略高成本的排版检查，并**不影响 DOCX 的生成、内容完整性和结构校验**。用户明确要求 PDF 交付物时仍必须生成 PDF。要求目录页码准确时，应通过适用 Office 排版引擎实际更新并验证；若未运行或用户选择跳过有关验证，明确标记“目录页码未验证”，不得把 `w:updateFields` 或 TOC/PAGE 域存在性视作页码正确。

## 实际排版检查路径（选择标准或严格时）

`--toc` 生成 Word 原生 TOC 域，页脚 PAGE 域只代表可更新结构。`w:updateFields` 不是已执行域更新的证据。用户需要准确页码时，使用适用的 Word/LibreOffice 排版引擎更新域、重分页、保存，再核对目录与实际页码。保留合法手写目录，重复目录须依据用户要求处理，不能按标题关键词擅自删除正文。

需要视觉检查时，可用 documents 渲染工具或实际 Office/PDF 排版链路生成页面图像；只检查选定级别要求的页面。对于标准模式，若排版引擎只能整份导出 PDF 才能取得抽样页面，应提前说明其时间成本并允许用户跳过，不能暗中执行高成本全页流程。严格模式才默认逐页检查。

启动 Office 应使用本任务独立会话，并为打开、更新、保存、导出设置超时；只清理本任务所属进程，不能关闭用户已有的 Office。Office 操作分别记录，单步可按文档规模设置合理超时；同一原因失败先诊断，有明确修正才重试一次，同因再失败即更换兼容路径或标明未完成，不无限等待。仅重新执行失败阶段，不重复已通过的内容检查。

## 阶段失败后的交付判断

交付物是否可用和检查是否完成必须分开判断。DOCX 的生成、可解析性、关键内容一致性与图形资源均已通过时，非交付要求的 PDF 辅助导出挂起，不得抹去已有成果；仍需明确目录页码与全页视觉的 `not_checked` 状态。如果用户明确要求 PDF 或完整视觉验收，这些未完成项仍是阻塞，不可声称全部完成。

探针不代替全量验证：最小 Mermaid/Word 转换只能证明依赖链可用；实际长文档仍按内容及用户必需的排版范围检查。对于 Office 的更新域、保存、导出分别记录操作结果、文件实际修改情况和异常；有原因证据才重试，重复挂起切换路径，不重新执行已验证的前序阶段。

## 交付状态必须拆开报告

交付 DOCX 并分别记录：输入→MD 融合完整性（若适用）、MD→DOCX 内容一致性、DOCX 结构、图形/公式、目录域存在性、目录实际页码更新/核对、视觉检查级别及实际范围。每项状态使用**通过 / 失败 / 未执行 / 用户选择跳过**，说明工具与仍存在的风险。

快速模式不得表述“全页视觉检查通过”；标准模式只能报告抽样页面；严格模式用户选择跳过时必须明确写出“全页视觉检查：用户选择跳过”。内容或结构检查失败不能作为已验收的完整文档交付；可交付现有阶段成果并报告准确缺口。
