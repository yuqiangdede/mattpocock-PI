# 非 Matt 文档 Skills：工具选择与分级验证策略

适用于引用本目录公共执行约定的文档 Skills，包括需求、总体/概要设计、数据库、接口、组件融合和 Markdown 转 DOCX。此策略约束工具选型与验证成本，不取代各 Skill 的业务事实、来源覆盖、字段完整性与交付要求。平台专有的图像生成和插件打包工具遵守其宿主 API 与安全协议，不因通用工具推荐策略而被替换。

## 工具选型：先判断最合适的方案，再检查已安装工具

1. 先识别输入输出类型、语法/协议/数据库方言、准确性、版式要求、规模、可复现性、离线/隐私/许可限制。比较可行工具在**结果质量、能力覆盖、稳定性、兼容性、维护/安装成本、执行时间**上的实际适用性；不能只因为系统已安装就默认选它，也不能只因为新工具更流行就要求安装。
2. 选出推荐方案后再核对运行环境：可执行文件、版本、权限、依赖和针对本次输入特性的最小探针。已安装但不适用视为不满足要求；已有工具达到质量目标且综合成本更低时，可以直接使用。
3. 推荐方案缺失或不兼容时，主动向用户说明：
   - 推荐工具/版本或能力要求及适用任务；
   - 相比现有方案的实质优势和安装/运行代价（含网络、权限、隐私、许可或费用）；
   - 安装范围与明确步骤（优先项目内、隔离或便携方式，不硬编码开发机路径）；
   - 已有可行替代方案及质量/功能损失，请用户选择。
   仅在选择确实影响交付、成本或环境时给出简短推荐；常见且成本低的已满足场景不反复问选型问题。
4. **不得未经明确授权自动安装、改变全局 PATH/系统设置、联网下载额外二进制或发送私有材料到外部服务**。用户选替代路径或拒绝安装后，继续可独立完成的部分，真实记录未满足的能力。不得把替代工具输出说成等同于原生目标格式。
5. 工具选型不得绕开平台安全契约，例如宿主提供的插件校验/打包 API、图像模型入口、只读源码/SQL 分析和生产系统写入许可；确实缺乏兼容执行器时记录阻塞，而不是假定任意工具都能替换原脚本。

## 验证分级与不可跳过的底线

- **必做：内容和结构检查。** 输入清单与章节/字段/对象覆盖、顺序与重复、业务编号和引用、链接与图形资产、目标文件可读性、关键数据/示例及源到目标的一致性，按各 Skill 原有专业标准检查。脚本仅证明实际覆盖的项目，抽检或关键短语存在性不等于全文一致。
- **快速：内容与结构。** 不为排版额外导出 PDF、渲染每页图片或启动耗时 Office 验证。普通 Markdown→DOCX 默认此级别；未做分页或目录实际页码检查要标记未验证。
- **标准：快速 + 代表性页面抽查。** 根据本次风险选择封面、目录、长表、复杂图形、公式或异常分页等少量页面。可借助现有 Office/DOCX 预览；如果只能通过导出 PDF 实现，先提示额外成本，用户可跳过。样本通过不代表全部页面。
- **严格：快速 + 实际排版引擎重分页/按需更新目录 + 全页渲染与视觉检查。** 用于正式客户交付、固定企业模板、要求准确目录页码或高版式风险；可推荐，但**全页视觉检查允许用户明确选择跳过**。目录页码是否更新、准确仍须单独报告，不因选择跳过视觉检查而声称已验证。
- 单纯的 Markdown 内容技能没有 DOCX/PDF 排版阶段时，无需弹出排版验证选择。用户明确要求 PDF 作为交付物时，生成 PDF 仍是交付义务，不得把“跳过排版验证”解读为“不生成 PDF”。要求精确分页/模板符合性时，应说明跳过对应检查会使该要求不可验证。
- 已知为内部草稿或一般转换且用户未指定级别，采用快速；已明确的正式排版或高风险条件，建议严格并解释额外成本。用户选定级别或明确跳过后，本次工作流沿用，不在每次写入/转换后反复询问；只有交付性质或风险显著变化时再提示。
- 无论级别，**不能跳过各 Skill 的完整性、事实证据、协议字段、迁移链及文件结构底线检查**。用户选择跳过的是高成本视觉检查，不是对遗漏、错误或损坏的免责。

## 增量执行与交付报告

- 继续遵守分块写入、现有文件快照、外部修改冲突保护、任务检查点、证据复用与失败阶段隔离；同一输入/环境/工具链和有效证据可复用，变更只重算受影响项，最终仍检查整体内容完整性。
- 失败不原样无限重试；定位失败阶段，保留已验证成果。替代工具的输出需重新进行本次必要验证。
- 交付分别报告：内容与结构、图形/公式转换、实际目录页码、抽样或全页视觉检查，状态使用**通过 / 失败 / 未执行 / 用户选择跳过**。准确说明样本范围、已用工具和未验证风险；不得以“文件存在”“关键短语存在”或“域已生成”笼统宣称完全通过。
