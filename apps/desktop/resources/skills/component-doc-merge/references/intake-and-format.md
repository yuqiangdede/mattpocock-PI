# 输入、命名与格式选择

## 收集提示

> 请提供以下信息：
> 1. 本次组件文档的路径或附件，以及产品范围；文档类型为需求、总体设计或概要设计。
> 2. 请人工指定最终文档名称（用于正文标题和 MD/Word 文件名）。
> 3. 上传或提供 Word 模板路径；没有模板时，请选择“正式交付版”“评审协作版”或“企业简洁版”。
> 4. 如有指定输出目录，请一起提供。

路径、附件和格式可分次提交，已回答的直接沿用。缺少名称或未决定模板/推荐格式时保持等待；推荐或预选不等于用户已选择。目录输入先列出候选文件供核对范围，排除旧版、QA、输出稿及无关文档，不能把所有 Markdown 自动纳入。

名称为文档标题和文件名主干，不要求用户手工填扩展名。用户给出完整 `.md/.docx/.doc` 文件名时取其主干；提供名称和输出文件名有实质差异时确认意图。路径分隔符、Windows 非法字符、保留设备名或目标文件冲突时让用户给出有效名称或明确选择，不暗自改成其他名称，不覆盖输入文件。

若混有需求与设计，先区分用途：需求可作设计范围依据，设计可用于核对现状，但输出仍为用户指定的一种文档。要求同时融合需求与设计时，分别人工指定名称并生成两份，保留相互引用，不强行混章。总体与概要深度混合时明确最终层次，保留必要内容归属，不丢弃细节或把概要冒充总体已验证事实。

## 推荐格式

这些是通用工程文档格式，不自动宣称符合某项国家、行业或企业标准。用户给出标准名称和版本时，另行核对实际条款。

| 选择 | 适用场景 | 内容结构与 Word 样式 | 转换标识 |
| --- | --- | --- | --- |
| 正式交付版（推荐） | 客户交付、归档、正式规格书 | 独立封面、自动目录、完整章节、页码；A4、正文 11 pt、深蓝标题、灰色表线 | formal |
| 评审协作版 | 内部评审、跨团队协作 | 封面、自动目录、清楚标识、较宽留白；A4、正文 11 pt、1.5 倍行距、蓝色表头 | review |
| 企业简洁版 | 日常技术交接、精简排版 | 标题区、自动目录、紧凑章节与表格；A4、正文 10.5 pt、黑灰标题，内容仍完整 | compact |

选择只改变章节呈现和版式，不省略权限、状态、异常、数据、接口、质量指标或验收边界。缺少的版本、作者、日期和审批信息不编造；修订记录仅在有真实记录时提供。

### 需求文档的推荐章节

产品概述与业务目标 → 范围与角色 → 业务场景/整体流程 → 按产品能力组织的功能需求 → 共用业务规则 → 数据需求 → 外部接口 → 非功能需求 → 验收要点与必要业务缺口。用例保留前置/后置条件、正常/可选/异常过程与可验证结果；根据输入内容裁剪空章节。

### 设计文档的推荐章节

产品目标与设计范围 → 约束与总体方案 → 能力与子系统协作 → 端到端核心流程 → 接口与数据设计 → 状态与异常恢复 → 集成部署 → 安全与质量策略 → 关键取舍及必要工程缺口。总体到系统与子系统层，概要按业务模块展开契约和机制；组件技术差异放在相应职责下，不另起多套总目录。

## 用户 Word 模板

读取模板实际的封面、章节组织、标题层级、中文/西文字体、段距、纸张、页边距、页眉页脚、目录、表格、图题与页码。区分“样式参考”与“保留固定封面/固定章节正文”，将这两类要求分别交接。模板中的示例产品、业务、机构、作者和审批不是本项目事实。

`.docx` 可直接作为 Pandoc 的 `--reference-doc`；它仅复用样式，不保留模板正文和固定封面。需要完整封面/固定版式时，通过已有 Word/DOCX 工具专项制作，再检查实际布局；不能仅传 reference-doc 就声称模板逐页复现。旧 `.doc` 须用实际兼容工具读取/转为 DOCX 样式参考，不能更名伪装。缺工具或读取失败时请用户选择可用推荐格式或提供可读模板，不静默替换。

## 交接字段

在 `.merge-work/交接记录.md` 记录：输入文件清单及组件/版本、最终文档类型、用户指定标题与文件名、输出目录、模板绝对路径及使用方式或 profile 标识、已确认决策、合并稿路径、图形资产目录、检查状态、是否继续 Word。人工已选值在转换阶段直接沿用。
