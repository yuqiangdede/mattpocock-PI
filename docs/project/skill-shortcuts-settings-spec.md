# 独立扩展设置与可配置 Skill 快捷按钮规格

> 历史规格，已被 [阶段一 Skill Launcher](skill-launcher-spec.md) 替代。下文保留讨论历史，不再作为实现依据；按钮位置、来源锁定和预置升级策略已撤回。

需求基线：2026-10-06 用户已确认的三轮需求及整体需求。状态：正式规格已整理；用户批准工单拆分时确认测试边界，7 张实施工单已发布为 Issue #31–#37。规格本身尚未发布为独立 Issue。功能尚未实现。

## Problem Statement（问题陈述）

用户无法自由调整现有 Matt Skill 按钮的名称、绑定、布局和用途说明，现有默认提示词设置只覆盖部分定制需要。另建一套自定义按钮会形成重复入口，而将扩展配置持续加入原生 PI 设置会增加同步上游时的维护与迁移成本。

用户需要一套统一的可编辑快捷按钮配置，以现有 Matt 按钮为预置，保留已修改的提示词，并让应用升级与 Skill 更新不打乱自己安排的工作界面。

## Solution（解决方案）

提供独立的“扩展设置 → 快捷按钮”。现有 Matt 按钮转为 Shortcut Preset（快捷按钮预置），与用户新增按钮共同由全局 Shortcut Configuration（快捷按钮配置）驱动。

用户可以新增、编辑、复制、排序、隐藏和删除按钮，配置名称、一个 Skill、默认提示词、备注、展示位置及启用状态。按钮显示在常用区域或更多菜单，点击只插入当前 Composer 草稿，保留文字与附件，用户编辑后手动发送。备注仅用于界面说明。

扩展设置页面、配置存储与代码模块独立于原生 PI 设置，应用继续统一打包发布。提供显式保存、可恢复备份、JSON 导入导出和明确的恢复操作；升级保留用户配置，预置变化由用户选择应用。

3. 作为应用用户，我希望修改现有预置按钮，以便直接调整常用入口。
4. 作为应用用户，我希望新建按钮，以便添加自己的工作用途。
5. 作为应用用户，我希望修改按钮名称，以便用自己熟悉的短名称识别动作。
6. 作为应用用户，我希望从全部已识别的可用 Skills 中选择绑定，以便使用 Matt Skills 和自己添加的 Skills。
7. 作为应用用户，我希望看见 Skill 来源，以便区分同名条目。
8. 作为应用用户，我希望重新绑定按钮的 Skill，以便用途变化后继续使用该按钮。

39. 作为已有用户，我希望旧提示词自动迁移且保持原值，以便升级后不丢失定制。
40. 作为已有用户，我希望默认提示词与显式空提示词的区别被保留，以便迁移不改变插入行为。
41. 作为已有用户，我希望应用和 Skill 升级不覆盖修改或恢复已删除按钮，以便保留自主选择。

43. 作为应用用户，我希望 Skill 不可用时保留按钮并说明原因，以便重新绑定而不丢失配置。
44. 作为应用用户，我希望绑定有歧义时禁止错误插入，以便避免使用错误来源的 Skill。
45. 作为应用用户，我希望配置损坏时保留原文件并提供恢复选择，以便避免被默认配置静默覆盖。
46. 作为多语言用户，我希望未自定义的预置内容随界面语言切换，以便理解默认用途。
47. 作为多语言用户，我希望自己修改的文本保持原文，以便切换语言不会覆盖定制。
48. 作为部署用户，我希望配置使用当前应用数据目录，以便复制部署或切换数据目录后不引用开发机器路径。
49. 作为维护者，我希望扩展配置与原生设置保持边界，以便降低同步上游的改动范围。

## Implementation Decisions（实现决策）

1. 扩展模块集中拥有预置定义、用户配置、校验、版本迁移、持久化、备份与编辑界面；原生设置导航和 Composer 仅提供必要接入。复用既有 Skill 目录与草稿插入能力。
2. 配置全局共享，独立于原生设置存储，位于应用解析出的数据目录；包含 schemaVersion。按钮绑定、备份及导出不得依赖开发机器绝对路径。
3. 每个按钮具有稳定 id、名称、单个 Skill 绑定、默认提示词、备注、常用或更多位置、启用状态；更多按钮另有现有分组归属。顺序配置决定常用区和更多组内顺序。
4. 保留现有探索、维护、协作与项目设置四组，不开放用户自建分组。生成规格和任务拆分默认迁入探索组，用户可调整为常用。
5. Matt 按钮仅作为可编辑预置，不保留另一套写死展示清单。预置身份与用户覆盖可区分，以支持恢复、语言切换、预置变化通知和删除选择保留。
6. 同一 Skill 可被多个按钮绑定，按钮独立拥有提示词等配置。Skill 来源必须可辨识；配置身份与当前上下文的实际指令解析分开，无法确定来源时明确提示冲突而不选取任意同名条目。
7. Skill 可用性依当前项目与会话解析。不可用或禁用时保留配置并说明原因，不修改草稿，提供配置入口，不自动安装或替换 Skill。
8. 点击按钮只向正常 Composer 草稿插入实际 Skill 指令与提示词。备注不进入插入内容；文字和附件保留；异步目录读取过程中切换项目或会话时，不将结果写入其他草稿。预览与最终插入对同一绑定及提示词保持一致。
9. 确认需求是独立固定操作，与工程流程面板一起排除在配置范围外。不受需求讨论按钮删除、隐藏、导入或整套恢复影响，保持既有内容版本确认语义。
10. 编辑采用显式保存与取消，成功保存后立即刷新展示；有未保存修改时离开需提示处理。保存失败保留编辑内容，Composer 继续使用上次成功保存的配置。
11. 未覆盖的预置名称、提示词与备注按当前语言解析；用户覆盖按字段保留原文。空字符串是明确空提示词，区别于未覆盖或旧配置 null 的默认语义。
12. 将旧默认提示词配置迁移到新结构。新配置存在时不重复迁移覆盖；旧值不主动删除。完成有效持久化后才算迁移成功，失败不损坏旧配置。
13. 更新应用或 Skill 内容不覆盖用户名称、绑定、提示词、备注、布局、启用状态和删除选择。新预置内容仅提示可选择添加或恢复。
14. 单个预置按钮恢复名称、Skill、提示词与备注，保留位置、排序、分组和启用状态。整套恢复还原预置与布局并移除自建按钮，执行前展示影响范围、确认和备份。
15. JSON 导出保留配置完整语义。导入先校验并展示整体替换范围，确认且备份成功后替换；无效导入保持原配置。导入包含当前机器不可用的 Skill 时保留绑定，以不可用状态处理。
16. 保存、导入、旧配置迁移与整套恢复前保留可恢复备份。首次无现有扩展配置时不虚构备份；迁移备份应能恢复旧提示词来源。备份失败时不继续覆盖，反馈失败；可从有效备份恢复配置。
17. 配置损坏或无法读取时保留原文件并明确提示，由用户选择备份恢复或恢复默认；加载失败不视为首次安装而自动写入默认值。写入失败保留上次成功存储的数据。
18. 首版只迁移快捷按钮与原有默认提示词设置，其他扩展设置保持既有行为。独立配置不等于独立安装包，应用统一发布。

## Testing Decisions（测试决策）

### 已确认的验证边界

优先复用现有 Electron 工程设置与 Coding Workbench 测试设施，在真实设置界面和 Composer 这一最高用户行为边界验证“编辑 → 保存 → 展示 → 插入草稿 → 重启保留”。不为每个内部组件另建测试入口。

持久化失败、迁移、备份恢复和无效导入等场景通过扩展配置公开读写边界进行补充验证，使用隔离测试数据与受控失败，不触碰用户实际配置。这是对存储异常覆盖的补充，不另建生产测试服务。

### 测试原则与参考

- 断言用户可见内容、发送与草稿行为、持久化结果及失败后的数据完整性，不断言组件拆分、内部状态或固定文件排列。
- 覆盖扩展设置、Composer 插入、Skill 解析、配置持久化与迁移；保留原生设置和固定非 Skill 操作的回归检查。
- 参考已有工程设置 Electron 用例、快捷按钮交互 Electron 用例、默认提示词测试及配置校验测试，复用草稿和附件观察方式。
- 按目标静态检查、目标模块测试、Electron 功能验证逐步扩大范围；需求整理阶段不声称功能已经验证。

## Out of Scope（范围外）

- 项目级配置覆盖、自定义更多菜单分组、多 Skill 串联、条件执行与自动发送。
- 自动安装或替换 Skill，修改 Skill 自身指令，独立扩展安装包与热更新。
- 迁移全部已有扩展设置，改造原生设置体系，自动执行 Workflow 或改变需求确认语义。
- 提交、推送、合并、应用打包与发布；本技能中的项目 Issue 发布为单独授权的规格交付动作。
