## T1：独立扩展设置与预置按钮的保存使用链路

### What to build（交付行为）

用户在独立扩展设置中看到完整 Matt 预置，编辑名称、默认提示词和备注，预览后显式保存；Composer 随即使用配置，点击仅插入草稿，重启保留。必要的配置模块边界调整纳入本切片，避免只交付不可使用的存储层。

### Acceptance criteria（验收标准）

- [ ] 扩展设置与原生设置分离，带版本配置位于当前应用数据目录；首次初始化完整预置，不维护第二套写死展示清单。
- [ ] 生成规格、任务拆分位于更多的探索组；确认需求及工程流程面板独立于需求讨论按钮存在。
- [ ] 可编辑预置名称、提示词、备注，预览实际插入内容；支持显式保存、取消和离开时未保存提示。
- [ ] 保存成功立即刷新且重启保留；保存失败保留编辑内容及 Composer 上次有效配置。
- [ ] 首次无配置可初始化；损坏或无法读取的已有配置保留原文件、明确报错，不当作首次启动静默覆盖。
- [ ] 保存前有效配置有可恢复备份；备份或写入失败不覆盖旧数据，首次无配置不虚构备份。
- [ ] 未覆盖的预置名称、提示词与备注随界面语言变化，逐字段自定义内容与显式空提示词保持原值。
- [ ] 复用现有 Skill 插入链路，保留草稿与附件，备注不发送，无自动提交或任务创建；保留异步草稿归属保护。
- [ ] 用真实设置和 Composer 完成保存、预览、插入与重启验证，并在配置公开边界验证读写失败保护及原生设置回归。

### Blocked by（阻塞项）

无，可立即开始。

## T2：旧提示词安全迁移

### What to build（交付行为）

已有用户首次使用新扩展设置时，旧提示词安全迁移并直接用于按钮。默认语义、显式空字符串和自定义文本保持不变，原数据仍可恢复。

### Acceptance criteria（验收标准）

- [ ] 旧提示词按对应预置身份迁移，null 使用本地化默认、空字符串仅插入 Skill、自定义文本原样保留。
- [ ] 新配置已存在时不重复迁移覆盖用户改动；旧字段保留用于兼容与恢复。
- [ ] 迁移前保留可恢复来源备份，成功有效持久化后才记录完成；备份或写入失败保留旧数据且明确提示。
- [ ] 迁移后的设置页面、Composer 插入与重启结果一致，包括中文与英文界面。
- [ ] 验证迁移失败后的重试以及新配置存在但损坏时不静默重建。

### Blocked by（阻塞项）

- T1。

## T3：按钮新增与布局管理

### What to build（交付行为）

用户新建或复制按钮，并控制常用位置、更多分组、排序、启用和删除。所有变更沿用显式保存和安全存储，同一 Skill 的多个按钮保持各自提示词。

### Acceptance criteria（验收标准）

- [ ] 新增和复制产生独立稳定身份，支持已可明确解析的 Skill；名称、提示词、备注独立编辑。
- [ ] 可选择常用或更多位置；更多仅提供探索、维护、协作、项目设置四组，组内与常用区域排序正确。
- [ ] 启用与隐藏保留配置，删除正确移除按钮；记录预置删除选择供升级保护使用。
- [ ] 同一 Skill 可有多个按钮并独立预览、保存、插入；支持全部按钮隐藏或删除而固定操作仍可使用。
- [ ] 修改布局后保存立即生效、取消不生效，重启与跨项目展示一致。
- [ ] 删除或隐藏需求讨论以及生成规格、任务拆分位置变更不影响确认需求和工程流程面板。
- [ ] 使用 Electron 验证完整新增、复制、布局调整、隐藏、删除和草稿插入流程；回归 T1 的保存与失败保护。

### Blocked by（阻塞项）

- T1。

## T4：全来源 Skill 绑定与上下文安全解析

### What to build（交付行为）

用户可为按钮绑定全部已识别的可用 Skills，包括自建 Skill；来源明确，绑定不依赖开发机器路径。项目或会话变化后，按钮重新按上下文解析，防止歧义和异步误插入。

### Acceptance criteria（验收标准）

- [ ] 选择器展示应用识别的完整可用 Skill 清单及来源，支持新建按钮绑定与已有按钮重新绑定。
- [ ] 同名多来源可区分；无法明确解析时显示冲突，不任意选择同名条目。
- [ ] 当前项目缺失、禁用或不可用时保留按钮和绑定，显示原因、不插入并提供配置入口，不自动安装或替换。
- [ ] 多按钮绑定同一 Skill 时配置彼此独立；预览与实际解析出的插入指令一致。
- [ ] 异步读取目录后项目或会话已切换，不修改其他草稿；保留文字、附件与手动发送约束。
- [ ] 跨项目和隔离数据目录验证来源绑定，绑定数据不硬编码开发机器绝对路径。
- [ ] 测试明确来源、同名歧义、不可用、禁用及异步切换场景，回归已有 Skill 使用流程。

### Blocked by（阻塞项）

- T3。

## T5：单项恢复、整套恢复与备份恢复

### What to build（交付行为）

用户可恢复单个预置内容、确认后恢复全部默认布局，或从有效备份恢复自己的配置。损坏配置有明确恢复入口，恢复失败不破坏原数据。

### Acceptance criteria（验收标准）

- [ ] 单项恢复仅还原名称、Skill、提示词、备注，保留位置、顺序、分组与启用状态，并恢复未覆盖内容的本地化语义。
- [ ] 整套恢复展示影响范围、确认后还原预置与布局，移除自建按钮且正确重置删除选择。
- [ ] 整套恢复前有可恢复备份；备份失败中止覆盖，取消不改变已保存配置。
- [ ] 可选择有效备份恢复，先校验再应用；无效备份不替换当前配置，操作结果与失败原因可见。
- [ ] 损坏或无法读取的当前配置原文件保留，用户明确选择恢复备份或默认；失败不静默覆盖。
- [ ] 恢复后 Composer 立即刷新且重启一致，固定非 Skill 操作不受影响。
- [ ] 验证单项、整套、取消、无效备份、备份失败、写入失败及恢复重启行为。

### Blocked by（阻塞项）

- T1。

## T6：JSON 导入导出与跨机器配置使用

### What to build（交付行为）

用户导出完整 JSON，在另一应用数据目录中导入；查看整体替换范围并确认后使用，迁移后布局与文本不变，缺失 Skill 保留绑定并明确提示。

### Acceptance criteria（验收标准）

- [ ] 导出保留预置覆盖、按钮身份、布局、启用状态、删除选择、Skill 来源及默认和显式空值语义。
- [ ] 导入先校验结构与版本，再展示整体替换影响；无效文件或不支持的版本不改变配置。
- [ ] 确认后先备份再整体替换，取消无变化；备份或写入失败保留原配置与可重试内容。
- [ ] 当前机器或项目缺失的 Skill 保留绑定，以不可用状态处理；同名歧义遵守 T4 解析规则。
- [ ] 在另一隔离应用数据目录导入后展示与插入结果符合原配置，重启保持；固定操作不受替换影响。
- [ ] 验证有效往返、非法导入、取消、存储失败及跨目录使用，不触碰真实用户数据。

### Blocked by（阻塞项）

- T3。
- T4。

## T7：预置变化通知与用户选择应用

### What to build（交付行为）

应用或 Skill 更新后，用户配置与删除选择保留。预置新增或变化通过通知供用户选择添加或恢复，操作前可理解影响，不自动重排或恢复删除按钮。

### Acceptance criteria（验收标准）

- [ ] 应用及 Skill 更新不覆盖用户名称、绑定、提示词、备注、位置、顺序、分组、启用状态及删除选择。
- [ ] 新增或变化预置有可理解提示，未选择应用不改变当前配置。
- [ ] 用户可选择添加新增预置或恢复变化预置；保存和备份沿用有效配置保护，选择不影响未选中的按钮。
- [ ] 恢复已有预置遵守单项恢复边界；已删除预置只能在用户明确添加或整套恢复后出现。
- [ ] 老用户迁移后、自建按钮和导入配置存在时，预置变更检测仍保留已有有效配置。
- [ ] 模拟预置版本变化、Skill 内容更新及应用重启，验证通知、选择、取消和保护规则。
- [ ] 汇总所有规格验收覆盖，完成原生设置与固定操作回归；仅报告实际运行的验证结果。

### Blocked by（阻塞项）
