# 快捷按钮与独立扩展设置需求

> 历史需求，已由 2026-10-06 的 [两阶段 Skill Launcher 需求](skill-launcher-spec.md) 替代。

状态：整体需求已由用户确认（2026-10-06），可作为后续实现与验收依据；当前仅完成文档整理。

## 目标与已明确方向

用户可在设置中配置界面按钮及其绑定的 Skill、默认提示词和备注。现有 Matt Skills 按钮作为新配置机制的预置配置默认展示，可以修改调整；界面由同一份按钮配置驱动。

新增配置与原生 PI 设置分离，降低后续同步上游、维护扩展功能的耦合。分离不意味着已经具备独立安装或热更新能力。

## 首版功能

- 独立的“扩展设置 → 快捷按钮”入口。
- 每个按钮具有稳定身份、名称、一个 Skill、默认提示词、备注、展示位置、启用状态；列表顺序决定展示顺序。
- 支持新增、编辑、复制、排序、隐藏、删除，保存前预览插入内容。
- Matt 现有按钮作为预置配置，不再额外保留一套写死的按钮列表。
- 点击按钮将 Skill 指令与提示词插入正常草稿，保留已有文字和附件，用户编辑后手动发送。
- 备注仅供界面说明，不进入发送内容；提示词允许留空。
- Skill 选择器包含应用识别的全部可用 Skills，包括用户自行添加的 Skills，展示来源。
- 恢复单个预置按钮、恢复整套默认配置；整套恢复前展示覆盖范围并确认。

## 分离边界

- 扩展设置页面、配置读写和校验、默认配置、迁移逻辑集中在扩展模块。
- 独立配置文件带 schemaVersion，存放在应用解析出的数据目录下，不硬编码开发机器路径。
- 原生设置导航和 Composer 保留必要接入点；实际 Skill 插入复用已有机制。
- 首版仅分离快捷按钮相关配置和原有默认提示词设置，其他扩展设置保持现有行为。
- 配置独立于 Skill 内容更新；按钮配置不修改 Skill 本身。

## 数据保护与升级

- 从 engineeringShortcutPrompts 迁移已有提示词；成功持久化新配置后才认为迁移完成。
- 已存在新配置时不重复迁移或覆盖用户调整；保留旧数据供兼容和恢复。
- 应用或 Skill 升级保留名称、顺序、隐藏状态、自定义提示词及用户删除选择。
- 新增或调整的预置内容提示用户选择添加或恢复，不自动改变当前布局。
- 配置无效或读取失败时明确提示，保留原始文件，避免用默认配置静默覆盖。
- Skill 缺失或禁用时保留绑定，显示不可用状态并允许重新绑定；不自动安装或替换。

## 决策树

已明确：统一可编辑预置按钮 → 扩展配置与原生设置分离。

第一轮已确认（用户接受全部建议）：
1. 分离设置界面、配置存储与代码模块；应用统一打包发布，首版不提供扩展独立下载安装。
2. 按钮配置全局共享，首版不提供项目覆盖。
3. 本次仅迁移快捷按钮与原有默认提示词设置，其他扩展设置后续处理。
4. 可绑定应用识别的全部当前可用 Skills，包括用户自行添加的 Skills；Matt Skills 是预置按钮来源。
5. 所有 Skill 按钮统一插入草稿，由用户编辑后手动发送；备注仅用于界面说明。

第二轮已确认（用户接受全部建议）：
6. 按钮选择常用区域或更多菜单，支持排序；更多菜单保留现有四个分组，允许选择所属分组，首版不开放自定义分组。
7. 工程流程面板、确认需求等非 Skill 操作保留原有入口，不纳入按钮配置。
8. 显式保存或取消；保存成功后立即刷新按钮，离开时对未保存修改提示处理。
9. 单个预置按钮恢复名称、Skill、提示词、备注，保留位置、排序和启用状态；整套恢复还原所有预置和布局并移除自建按钮。整套恢复前展示影响范围、确认并备份。
10. 升级保留用户配置和删除选择，新预置内容提示用户选择添加或恢复，不自动改变布局。
11. 首版支持 JSON 导入导出；导入校验后展示整体替换范围，确认并备份后替换。保存、导入、旧配置迁移前保留可恢复备份。

## 当前代码核对

- CodingWorkbench 当前更多菜单有 exploration、maintenance、collaboration、projectSetup 四组。
- 需求讨论当前为分裂按钮，其子菜单包含生成规格（spec）与任务拆分（tickets）；确认需求组件同时依附需求讨论的渲染分支。新配置允许隐藏或删除需求讨论，因此必须明确解除非 Skill 入口对此按钮的依赖。
- engineeringShortcutPrompts 当前支持 null（使用本地化默认提示词）和空字符串（仅插入 Skill），迁移应保留二者区别。

第三轮已确认（用户接受全部建议）：
12. 生成规格与任务拆分迁入“更多 → 探索”，也可配置为常用；确认需求作为固定独立操作保留，解除对需求讨论按钮的依赖。
13. 允许多个按钮绑定同一 Skill，分别配置名称与提示词；同名 Skill 展示来源，无法明确解析时提示冲突，不静默选择。
14. Skill 在当前项目不可用时保留按钮、显示原因、禁止插入并提供配置入口。配置损坏时保留原文件，由用户选择备份恢复或恢复默认。保存失败保留编辑内容，Composer 继续使用上次成功保存的配置。未自定义的预置名称、提示词与备注随界面语言切换，用户修改内容保持原文，空提示词表示仅插入 Skill。

## 交互与范围补充

- 全局配置中的 Skill 绑定在当前项目和会话上下文解析可用性，用户自建按钮不保证在所有项目都有对应 Skill。
- 预置与用户覆盖区分记录；旧提示词 null 保持默认语义，空字符串保持显式空值语义，不能互相转换。
- 非 Skill 固定操作不受按钮隐藏、删除、导入或整套恢复影响。
- 首版不提供项目配置覆盖、自定义更多分组、多个 Skill 串联、自动发送、自动安装或独立扩展发布。

## 验收标准

1. 首次启动按预置配置显示现有 Skill 按钮；生成规格和任务拆分默认位于“更多 → 探索”。
2. 编辑名称、绑定、提示词、备注、位置、顺序和启用状态后，界面同步变化且重启保留。
3. 点击按钮得到预览一致的插入内容，已有草稿和附件保留，备注不进入发送内容。
4. 旧提示词迁移后保持原值，重复启动不覆盖新配置。
5. 模拟应用升级及 Skill 更新，用户配置和删除选择保留。
6. 缺失 Skill、损坏配置和保存失败均有可见反馈，用户原始配置可恢复。
7. 原生设置功能与已有 Skill 使用流程通过回归验证；新增中文文案可读。
8. 新增、复制、隐藏、删除及同一 Skill 的多个按钮按各自配置独立工作；更多菜单分组和组内顺序正确。
9. 显式保存后立即生效，取消不改变已保存配置，离开未保存页面时提示处理；保存失败可继续编辑和重试。
10. 删除或隐藏需求讨论后，确认需求与工程流程面板仍可使用，不创建自动任务或发送消息。
11. 单项恢复只还原四项内容；整套恢复正确移除自建按钮并还原布局，执行前确认并保留可恢复备份。
12. JSON 导出与导入保留配置语义；无效导入不改变当前配置，合法导入确认后整体替换且可从备份恢复。
13. 同名多来源 Skill 可区分；歧义或当前项目不可用时不插入错误指令，有明确原因与配置入口。
14. 切换语言后未自定义预置内容随语言变化，自定义文本与显式空提示词保持原值。
15. 配置存储位于当前应用数据目录，切换数据目录或复制部署不引用开发机器绝对路径；配置与原生设置相互独立。
